# 프론트엔드 개발자 윤창식입니다.

여러 서비스가 공유하는 코드를 설계하고, 변경의 영향을 검증하며 개발 과정을 개선해 왔습니다. React·TypeScript 기반 제품 개발부터 API 이관, 디자인 시스템 자동화까지 제안과 구현을 맡았습니다. AI가 만든 결과는 타입·테스트·화면 검증과 직접 검수를 거쳐 적용합니다.

[이메일](mailto:wise@caesiumy.dev) · [GitHub](https://github.com/CaesiumY) · [LinkedIn](https://www.linkedin.com/in/chang-sik-yoon/) · [블로그](https://caesiumy.dev/)

## 주요 개발 경험

### 한국기술마켓

**프리랜서 프론트엔드 개발 | 2024.05 ~ 2026.05**

[한국기술마켓](https://kotechmarket.com/) · [한국기술허브](https://kotechhub.com/)

유저·관리자 앱의 전반적인 개발과 공통 구조 설계를 담당했습니다. 프론트엔드 개발자 2명 중 동료는 에디터 등 특정 기능을 맡았으며, 고객별 디자인과 기능이 다른 앱들을 함께 운영했습니다.

- **공통화의 경계와 변경 검증:** 앱마다 중복된 로직을 수정해야 하는 비용을 줄이기 위해 Turborepo 기반 모노레포를 제안·구축했습니다. 인증·공통 UI·테스트를 패키지로 공유하고 브랜드별 스타일은 앱의 토큰 오버라이드로 분리했습니다. 공통 속성 삭제가 다른 앱의 빌드를 깨뜨린 일을 계기로 검증 범위를 확대하고, 재사용하는 E2E 모듈을 파일럿 검증 후 앱들에 적용했습니다.
- **API 클라이언트 점진적 이관:** 잦은 Swagger 변경을 수기로 반영하는 부담을 줄이기 위해 Orval 코드 생성을 도입했습니다. 초기 AI 일괄 이관에서 회귀를 발견한 뒤, API별로 기존 요청·응답과 생성 코드의 호환성을 대조하고 Vitest·RTL·Playwright 검증 후 다음 대상으로 확장했습니다. 약 100개 엔드포인트를 이관하고 운영에도 나눠 배포했습니다.
- **API 변경 대응 절차 정착:** 기능 개발·테스트·배포 전에 최신 스키마로 코드를 재생성하도록 워크플로우에 통합했습니다. AI가 변경점과 작업 계획을 제시하면 직접 승인한 뒤 진행하도록 구성해, 자동 생성과 변경 판단을 분리했습니다.
- **디자인 시스템 생성·검수 자동화:** 반복하던 Figma 노드 전달을 JSON 매핑으로 정리하고 Storybook·디자인 토큰 생성에 연결했습니다. 생성 구조가 매번 달라지는 문제는 모범 사례 기반 정적 검사로 컴포넌트 누락·과잉을 확인하고 AI가 수정하는 루프로 대응했습니다. 타입·빌드 검사와 Playwright MCP의 화면 확인 후 직접 검수했으며, 공통 구조 재사용과 AI 활용으로 신규 앱 개발을 예상 3개월 대비 실제 3주에 완료했습니다.
- **위젯 단위 오류 격리:** 개발 환경의 API 실패가 화면 전체에 영향을 주는 문제에 대응해 Suspensive·ErrorBoundary를 개별 위젯에 적용했습니다. 추천 게시글 조회가 실패해도 해당 영역만 오류 화면으로 전환하고 나머지 영역은 정상 동작하도록 구성했습니다.

### 교육 지원 플랫폼

**프리랜서 프론트엔드 개발 | 2025.05 ~ 2026.01**

[충북 교육 지원 플랫폼](https://www.chungbook-e.com/)

- 유저·관리자 화면을 개발하고 유지보수를 담당했습니다. MSW 기반 모킹과 Orval·TanStack Query 코드 생성을 활용해 백엔드 구현을 기다리는 동안에도 프론트엔드 개발을 진행했습니다.
- Linear 로드맵과 MCP 기반 이슈 관리를 통해 클라이언트가 작업 진행 상황을 확인할 수 있도록 했습니다.

### KC Softmax(현 ML2)

**프론트엔드 엔지니어 | 2022.03 ~ 2023.09**

[회사 소개](https://www.kc-ml2.com/) · 반도체 기업 AI 연구 조직

- **데이터 계약의 중복 관리 해소:** 프론트엔드·백엔드가 각각 관리하던 바이너리 데이터 매핑의 동기화 부담을 줄이기 위해 gRPC·Protobuf 도입을 제안하고 전환을 진행했습니다. S3·CDN을 스키마의 단일 공급원으로 구성해 빌드 전에 다운로드하도록 자동화하고, 동료들에게 README 사용 가이드를 배포했습니다.
- **실시간 HUD의 렌더링 개선:** 실시간 시뮬레이터의 React HUD에서 갱신 주기가 다른 상태를 분리했습니다. React 개발자 도구의 렌더링 하이라이트로 비실시간 영역이 고빈도 데이터 갱신에 따라 반복 렌더링되지 않는 것을 확인했습니다.
- **개발·빌드 환경 전환:** 긴 대기 시간과 복잡한 Webpack 설정을 개선하기 위해 CRA·craco에서 Vite로 전환할 것을 제안하고 마이그레이션을 담당했습니다. 개발 서버 시작과 배포용 빌드에 걸리는 시간을 줄였습니다.
- **콘텐츠 관리의 개발자 의존도 완화:** 번역 파일을 S3·CDN으로 분리해 문구 수정마다 앱을 배포해야 하는 부담을 줄였습니다. 사내 블로그는 Notion API 기반 CMS로 구성해 비개발자가 콘텐츠를 등록·수정하도록 했습니다.

프리랜서 프로젝트는 일부 재직·교육 활동 기간과 병행했습니다.
