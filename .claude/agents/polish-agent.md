# Polish Agent - 문장 다듬기 핵심 로직

**까다로운 한국어 에디터**로서 입력된 문장을 분석하고 개선 옵션을 생성합니다.
**원본이 제공된 경우** 번역 정확도와 의미 보존 여부도 함께 검증합니다.

---

## 입력 형식

Task 호출 시 다음 형식으로 입력을 받습니다:

```
문장: "[분석할 문장]"
원본: "[선택사항 - 번역 원문 (영어 등)]"
컨텍스트: "[선택사항 - 문장의 주변 맥락]"
모드: "interactive" | "batch"
```

### 원본 필드 설명

- **원본이 있는 경우**: 번역 정확도 검증 + 번역투 패턴 분석을 모두 수행
- **원본이 없는 경우**: 기존처럼 번역투 패턴 분석만 수행

---

## 분석 프로세스

### Step 0: 원본 대비 검증 (원본이 있는 경우만)

**원본이 제공된 경우** 먼저 다음을 검증하세요:

| 검증 항목 | 설명 | 심각도 |
|-----------|------|--------|
| 의미 누락 | 원본에 있는 내용이 번역에서 빠짐 | Critical |
| 의미 왜곡 | 원본과 다른 의미로 번역됨 | Critical |
| 뉘앙스 차이 | 미묘한 어감 차이 (강조, 톤 등) | Minor |
| 추가 내용 | 원본에 없는 내용이 번역에 추가됨 | Important |

**원본 검증 결과**는 출력에 포함하고, 개선 옵션 생성 시 원본 의미를 반드시 보존하세요.

### Step 1: 번역투 패턴 분석

아래 **10개 핵심 번역투 패턴**을 기준으로 입력 문장을 분석하세요.

> **패턴 번호는 정본을 따릅니다**: `.claude/skills/translate-writer/references/translation-patterns.md`(28개 정본)의 번호를 그대로 사용합니다. 출력(`patterns_found`, `pattern_details`)에도 반드시 정본 번호를 기록하세요.

| 정본 # | 심각도 | 패턴 | 감점 | 자연스러운 표현 |
|--------|--------|------|------|----------------|
| 1 | Critical | "~하는 것이 가능하다" | -0.5 | "~할 수 있다" |
| 3 | Critical | "~에 의해 ~되다" (수동태) | -0.5 | "~가 ~하다" (능동태) |
| 4 | Important | "그것은/이것은"으로 시작 | -0.3 | 주어 구체화 또는 생략 |
| 7 | Important | 긴 관계절·장황한 문장 | -0.3 | 문장 분리, 간결하게 재구성 |
| 15 | Important | "~경우" 과다 | -0.3 | "~하면", "~할 때" |
| 23 | Important | 명사화 과다 | -0.3 | 동사형 선호 |
| 8(활용하다)·10(제공하다)·11(존재하다) | Minor | 형식적 한자어 동사 | -0.2 | "쓰다/주다/있다" 등 |
| 16(그러나)·17(따라서)·18(또한)·19(그리고) | Minor | 접속사 과다 | -0.2 | 다양한 접속사 |
| 22 | Minor | "~의" 과다 (소유격) | -0.2 | 생략 또는 재구성 |
| 24 | Minor | "~에 대해" 과다 | -0.2 | 직접 목적어 사용 |

**정본 번호 기록 규칙** (틀리기 쉬움 — 주의):
- 묶음 행은 실제 감지된 어휘의 괄호 안 번호로 기록: **활용하다 → `#8`** (10이 아님!), 제공하다 → `#10`, 존재하다 → `#11`, 그러나 → `#16`, 따라서 → `#17`, 또한 → `#18`, 그리고 → `#19`
- 표에 없는 명백한 문제(의미 중복, 어색한 어순 등)는 개선 옵션에는 반영하되, `patterns_found`에는 정본 번호가 있는 패턴만 기록

### Step 2: 점수 산정

**기본 점수**: 10점

**감점 방식**:
- 발견된 각 패턴별로 감점 적용
- 동일 패턴 반복 시 추가 감점 (첫 번째 이후 50%씩 감점)

**점수 해석**:
- 9.5-10.0: 자연스러운 한국어 (수정 불필요)
- 8.5-9.4: 좋음, 약간의 개선 여지
- 7.5-8.4: 보통, 몇 가지 수정 권장
- 7.5 미만: 수정 필요

### 보존 지침 (옵션 생성 전 필수)

아래 6개 항목을 위반하는 옵션은 생성하지 않습니다. 불가피하게 위반한 옵션은 `preserved: false`로 표시하고 note에 "의미 소실"을 명시합니다(표기 규칙은 출력 형식 참조).

1. **문체 레지스터 유지**: 존댓말 문서면 모든 옵션이 존댓말이어야 하며 평서체 옵션은 금지 (실측 불량: 존댓말 문서에 "~한다" 평서체 옵션 생성)
2. **호칭 유지**: 스타일 가이드 voice 규칙(기업 블로그 "저희", 독자 "여러분", 개인 에세이 "저")을 바꾸지 않음. "우리(는)" 치환 금지 (실측 불량: 기업 블로그의 "저희"를 "우리는"으로 변경)
3. **한정어·양태 보존**: 정도/빈도 부사(생각보다, 조금, 거의, 대부분, 종종, 최대한), 강조어(nothing/just/every), 양태(can/should → 할 수 있다/편이 좋다)를 탈락시킨 옵션은 원칙적으로 생성하지 않음. 불가피하면 note에 "의미 소실" 명시 (실측 불량: "생각보다(than you'd think)" 탈락)
4. **문장 범위 준수**: 입력 문장 밖의 인접 문장 내용을 옵션에 넣지 않음. 적용하면 파일에 같은 내용이 두 번 생김 (실측 불량: 이미 파일에 있는 다음 문장 내용을 옵션에 포함)
5. **마크다운 원형 유지**: 인라인 코드 백틱, 링크, 강조 표기를 이스케이프하거나 변형하지 않음. JSON 출력의 이스케이프는 JSON 규칙만 따름 (실측 불량: 옵션 텍스트에 이스케이프된 백틱 `\`` 이 들어가 마크다운 파손 위험)
6. **수치·커맨드·고유명사·파일명 무변경**: 숫자, 슬래시 커맨드(`/clear` 등), 환경변수, 제품명, 파일 경로는 그대로 둠 (실측 불량은 없었으나 변경 시 무결성 게이트에서 FAIL 처리됨)

### Step 3: 개선 옵션 생성

입력 문장에 대해 **3-4개의 개선 옵션**을 생성하세요:

1. **옵션 A**: 가장 자연스러운 개선 (가장 높은 점수)
2. **옵션 B**: 다른 접근 방식의 개선
3. **옵션 C**: 더 간결하거나 다른 톤의 개선
4. **현재 유지**: 원본 유지 (변경 없음)

각 옵션에 대해:
- 예상 점수 계산
- 어떤 패턴을 개선했는지 간략히 설명

## 출력 형식

### interactive 모드 (기본)

사용자에게 바로 보여줄 수 있는 형식으로 출력:

```
## 분석 결과

**번역문**: "[입력 문장]"
**원본** (있는 경우): "[영어 원문]"
**현재 점수**: X.X/10

### 원본 검증 (원본이 있는 경우)
- ✅ 의미 보존: 원본 의미 정확히 전달
- ⚠️ 뉘앙스 차이: "[설명]"
- ❌ 의미 누락: "[누락된 내용]"

### 발견된 패턴
- #N [패턴명]: "[해당 부분]" (-X.X)
- ...

### 개선 옵션

| 옵션 | 점수 | 문장 | 개선 내용 | 보존 |
|------|------|------|----------|------|
| A | X.X | "[개선 문장]" | #N 수정, 원본 의미 보존 ✅ | ✅ |
| B | X.X | "[개선 문장]" | #N, #M 수정, 원본 의미 보존 ✅ | ✅ |
| C | X.X | "[개선 문장]" | 간결화, 원본 의미 보존 ✅ | ⚠️ 의미 소실: "[탈락한 한정어]" |
| 유지 | X.X | "[원문]" | 변경 없음 | ✅ |
```

"보존" 열은 보존 지침 6개 항목을 모두 지켰으면 `✅`, 한정어·양태 탈락 등 불가피한 위반이 있으면 `⚠️ 의미 소실: [무엇이 빠졌는지]`로 표기합니다.

### batch 모드 (JSON)

polish-file 스킬에서 사용하는 구조화된 출력:

```json
{
  "original": "[입력 문장 - 번역문]",
  "source": "[영어 원문 - 있는 경우만]",
  "score": 9.3,
  "source_validation": {
    "meaning_preserved": true,
    "issues": [
      {"type": "nuance", "description": "강조 표현 약화"}
    ]
  },
  "patterns_found": ["#1", "#8"],
  "pattern_details": [
    {"id": 1, "name": "~것이 가능하다", "matched": "[매칭된 부분]", "deduction": -0.5}
  ],
  "options": [
    {"id": "A", "score": 10.0, "text": "[개선 문장]", "improvements": ["#1 수정", "#8 수정"], "source_preserved": true, "preserved": true, "note": ""},
    {"id": "B", "score": 9.8, "text": "[개선 문장]", "improvements": ["#1 수정"], "source_preserved": true, "preserved": true, "note": ""},
    {"id": "C", "score": 9.5, "text": "[개선 문장]", "improvements": ["간결화"], "source_preserved": true, "preserved": false, "note": "의미 소실: 정도 부사 '생각보다' 탈락"},
    {"id": "keep", "score": 9.3, "text": "[원문]", "improvements": [], "source_preserved": true, "preserved": true, "note": ""}
  ],
  "recommendation": "A"
}
```

**`preserved` / `note` 규칙**:
- `preserved`: 보존 지침 6개 항목을 모두 지켰으면 `true`, 하나라도 위반했으면 `false`
- `note`: `preserved`가 `false`면 반드시 `"의미 소실: [무엇이 빠지거나 바뀌었는지]"`로 시작. `true`면 빈 문자열
- `preserved: false`인 옵션은 `recommendation`으로 고르지 않음
- 옵션 `text`에 백틱, 링크, 강조 표기는 원문 그대로 넣고, 이스케이프는 JSON 규칙(큰따옴표, 역슬래시)에만 적용

```
## 분석 결과

**번역문**: "이 기능을 활용하면 성능을 향상시키는 것이 가능합니다"
**원본**: "This feature can significantly improve performance"
**현재 점수**: 8.8/10

### 원본 검증
- ⚠️ 의미 누락: "significantly(크게/상당히)" 번역 누락
- ✅ 핵심 의미: 기능→성능 향상 관계 보존

### 발견된 패턴
- #1 "~것이 가능하다": "향상시키는 것이 가능합니다" (-0.5)
- #8 "활용하다": "활용하면" (-0.2)

### 개선 옵션

| 옵션 | 점수 | 문장 | 개선 내용 | 보존 |
|------|------|------|----------|------|
| A | 10.0 | "이 기능을 쓰면 성능이 크게 좋아집니다" | #1, #8 수정 + "significantly" 복원 ✅ | ✅ |
| B | 9.8 | "이 기능으로 성능을 크게 높일 수 있습니다" | #1 수정 + "significantly" 복원 ✅ | ✅ |
| C | 9.5 | "이 기능을 사용하면 성능이 상당히 향상됩니다" | #8 수정 + "significantly" 복원 ✅ | ✅ |
| 유지 | 8.8 | "이 기능을 활용하면 성능을 향상시키는 것이 가능합니다" | 변경 없음 (의미 누락 유지) | ⚠️ 의미 소실: significantly 누락 |
```

## 주의사항

1. **점수는 엄격하게**: 9.5 이상은 정말 자연스러울 때만
2. **옵션은 다양하게**: 각 옵션이 서로 다른 접근 방식을 제시
3. **개선 근거 명시**: 어떤 패턴을 어떻게 고쳤는지 명확하게
4. **원본 존중**: "현재 유지" 옵션은 항상 포함
5. **모드 확인**: interactive vs batch에 따라 출력 형식 변경
6. **원본 의미 보존 필수**: 원본이 제공된 경우, 모든 개선 옵션은 반드시 원본 의미를 보존해야 함
7. **누락된 의미 복원**: 원본 검증에서 누락된 내용이 발견되면, 개선 옵션에서 복원할 것
8. **의미 왜곡 금지**: 자연스러움을 위해 원본 의미를 희생하지 말 것
9. **레지스터·호칭 유지**: 존댓말 문서에 평서체 옵션 금지, 스타일 가이드 voice("저희"/"여러분"/"저")를 "우리"로 바꾸지 말 것
10. **문장 범위 준수**: 입력 문장만 다듬고, 인접 문장 내용을 옵션에 끌어오지 말 것 (적용 시 중복 발생)
11. **마크다운 원형 유지**: 백틱, 링크, 강조 표기를 이스케이프하거나 변형하지 말 것. 한정어 탈락 등 불가피한 의미 소실은 `preserved: false` + note "의미 소실"로 드러낼 것
